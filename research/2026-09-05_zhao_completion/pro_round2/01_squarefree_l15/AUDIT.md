# 边界及红队审计

## 证明攻击面

**完整纤维与抽取子族。** 证明显式要求对每个七元 0/1 向量的双向条件 (F)。删除层数的是全部零和补集；点度 5 也必须是该完整族的点度。旧模型的 15 块确实满足所列块和，但其实际完整族含 238 块。本证明不允许把二者互换。

**模 5 符号。** 四层补集大小 7、6、5、4 对应零和长度 14、15、16、17，符号依次为正、负、正、负。逐二点三式的线性组合是 `(210,21,-15,10,-6)`，约化后恰为 `a-d`，不是 `a+d`，也不是孤立的 `a=0`。独立脚本检查了全部 625 个剩余类四元组。

**十项零和是否重复使用位置。** 每个固定二点删除集的四元块余下两个位置具有相同和值。共享其中一点必使另一点标签相等；平方自由性迫使它也是同一个位置。因此不同二元集两两不交，选五组得到真正十位置子集，而非多重和值表示。

**类大小 7。** 从整数方程本身确实还会出现 r=7、d4=0，不能无理由忽略。只有因为完整纤维是互异位置子集的集合，五个七元块不能全部等于同一七点类，才排除这一情形。一个明确的抽象伪模型是：把三组互不相交的七元集合各重复五次。它是 15 块、7-一致、5-正则的多重族，点类均为 7；因此块互异性必须保留。这一伪模型不满足完整纤维的集合语义。

**最后一步整数性。** 不使用任何实数或有理数松弛。单点类及四点类给出 4|C4|=210-20t；右侧恒为 2 模 4。若允许分数块数，可形式上取 |C4|=52.5-5t，所以该松弛不会给出这里的整数矛盾。必要条件可行也从未被解释为可实现标签。

**17 项原子。** 没有假设平方自由 17 项原子不存在；完整 C4 被保留，且正是其逐点整数度数导致矛盾。无须 Strong Davenport 常数的额外分类。

**平均交数。** 不使用平均块交数 2，更不把它当成逐对交数。用到的逐对约束分别由点度 5 与十位置零和论证直接得到。

**补集长度。** 排除 18 至 21 零和时，取其中一个 14 至 17 的零和，余下是 1 至 7 个位置的非空零和。该差集论证不假定整个 S 的和为零。

**位置和规范化。** 全程保留 21 个位置；没有平移、仿射归一化、逐列缩放或更换子集计数语义。行模式相等只是一个等价关系，不是选择部分轨道。结构分母计算保留全部标号点，不使用图规范标号器。

## 旧伪模型的主动重验

测试数据来自已经成功读取的 GitHub 文件：

- 仓库 `randomcat4/zhao`，PR 1；固定提交 `9d33328880a13609f047905af14e530172b42ae3`。
- 文件 `research/2026-09-05_zhao_completion/pro_round1/01_squarefree.md`。
- 该文件远端 blob SHA 为 `32bb34b5e37c39ee84b717bfab5ed358c559fad4`。

本地 `sources/known_false_model.json` 是其中明确数据的转录，不声称其字节与原 Markdown 文件相同。

算法一是 C++ 逐掩码的最低置位递推，使用五进制和值码。算法二是 Python 的 10+11 位置折半，使用四元组模 5 运算和和值／长度桶。两种实现没有调用彼此的求和逻辑。

算法一处理全部 2,097,152 个掩码。算法二生成全部 1,024 与 2,048 个半集，按唯一的左右分解精确计数全部 2,097,152 对；不是只检查找到的首个零和。两者在所有长度 0 至 21 的零和数和完整 4、5、6、7 元纤维的全部掩码列表上相同。

旧模型长度 1 至 13 的零和数依次是：

`0, 0, 4, 17, 34, 89, 236, 332, 450, 637, 641, 454, 328`。

合计 3,222。零基位置 `{0,7,20}` 是明确三项零和。完整七元纤维是 238，而非 15；四元、五元、六元完整纤维数分别是 18、32、94。所给 15 块的交分布核查为 `0:10,1:25,2:25,3:45`。给定补集线性组合的系数还被精确核查，得到支撑 `{0,4,5,11,12,15,16}` 的权 7 二进制核向量。

这些检查是反驳测试，不用于证明新的全称结论。

## 整数溢出审计

- 大结构数、容斥和使用 Boost `cpp_int`，校验器使用 Python 任意精度整数。
- 二项式表仅到 21；表内最大值为 C(21,10)=352716。
- 递推乘数计算的是一些七位置子集的数量，不超过 C(21,7)=116280。
- 分拆系数及其中间正因子乘积均不超过 15!=1307674368000，安全落在 uint64_t。
- 状态编码为六个五位剩余度桶及五个四位列组计数，严格小于 2^50，无碰撞；独立校验器往返解码每个状态。
- 调用数 527,334、转移数 527,250，远小于 uint64_t 容量。递推深度不超过 15。
- 全子集检查使用 uint32_t 掩码，界为 2^21；最低置位函数仅用于非零掩码。
- 和值表存入 uint16_t 的数小于 625；uint8_t 重量至多 21；uint64_t 计数至多 2^21。
- Python 折半实现不依赖固定宽度整数。
